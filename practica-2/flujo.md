Investigando encontre que GitFlow es un modelo de ramas donde hay varias ramas que se mantienen por mucho tiempo, no solo una. Esta main, que es lo que ya esta funcionando en produccion, y develop, que es como una rama intermedia donde se van juntando los cambios antes de que lleguen a main. Aparte de eso hay ramas mas especificas: feature/ para hacer una funcion nueva, release/ cuando ya se esta preparando una version para publicar, y hotfix/ para arreglar algo urgente que se rompio en produccion. Entiendo que este modelo se usa mas en proyectos donde hay que sacar versiones planeadas (tipo v1.0, v1.1, y asi sucesivamente) o cuando el equipo es grande y necesita mas orden y control antes de que algo llegue a produccion.

Trunk-based development es mas simple de entender: basicamente casi todo el trabajo pasa por una sola rama principal (main o trunk). Las ramas que se crean para hacer cambios duran muy poco, a veces ni un dia entero, y se mergean rapido de nuevo a main. No hay tantas ramas dando vueltas al mismo tiempo como en GitFlow.

Para una aplicacion web yo usaria trunk-based development, principalmente porque las apps web no se instalan como un programa, entonces no hace falta mantener varias versiones distintas funcionando a la vez — siempre hay una sola version corriendo, la que esta en produccion. Tambien me parece que integrar cambios seguido evita que se acumulen muchos conflictos al mergear, y si algo se rompe se nota mas rapido porque no pasan semanas juntando cambios de golpe. Ademas vi que trunk-based combina mejor con CI/CD, porque cada vez que se sube algo a main se puede desplegar automatico sin tanto proceso extra.
